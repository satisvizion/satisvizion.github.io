PrefabCapsule

An editor-only tool that turns any prefab into an encapsulated module. Collapse it to one governed node in the Hierarchy, expose exactly the properties a designer should touch, and guard the source asset from accidental Apply — with zero runtime footprint.

Unity 2022.3 LTS+ Editor-only · Zero runtime cost Built-in / URP / HDRP No-code workflow
ⓘ
One idea, four moves: Seal → Expose → Adopt/Govern → Ship. Add a PrefabCapsule component to Seal a prefab instance into a single governed node, Expose a curated surface of members onto that node, Adopt the overrides an existing project already has (and govern who sees what), then Ship — the marker component carries no runtime logic and is stripped from built scenes.
✅
Non-destructive by design. The Seal is an editor-only visualization — children stay present at runtime, your prefab data is never rewritten, and the capsule config is stored as primitive, diffable values. Remove the component and everything is exactly as it was.

🔒 Seal in one click

Collapse a busy prefab instance to a single locked node — the Hierarchy stops being a wall of children.

📝 Curated surface

Allow-list exactly the properties, methods and references a designer may touch, grouped into named Facets.

🛡 Apply Guard

Stop accidental Apply of instance overrides back to the shared asset — while Revert always works.

🔎 Adopt existing work

Inventory the overrides already scattered across your scenes, then Reveal them as a Facet or Clean them in one click.

📊 Capsule Health

A project-wide dashboard for broken exposes, empty capsules and drift — plus a headless CI validator.

Menu items and a custom Inspector do the whole workflow. The API is there when you want it.

This guide starts with install and a quick start, walks the four-move flow, then documents each pillar in its own page. The prominent Editor Tools / No-Code page and the Scripting API reference are near the end.

⤓ Installation

Import once, seal a prefab. There is nothing to configure and no runtime setup.

Import from the Asset Store
In Window → Package Manager → My Assets, download and import PrefabCapsule. It lands at Assets/PrefabCapsule/.
Read the Welcome window
A first-run Welcome window opens once automatically. Reopen it any time from Tools → PrefabCapsule → Welcome.
(Optional) Import the demo dependencies
The interactive demo scene uses com.unity.ugui and com.unity.inputsystem. Add them in the Package Manager if you want to open and play the demo — the core tool needs neither.
Seal your first prefab
Select a prefab instance in a scene and choose GameObject → PrefabCapsule → Seal Selected Prefab. See the Quick Start.

Requirements

  • Unity 2022.3 LTS or newer (compile-verified on 2022.3.56f1; developed on Unity 6000.0).
  • Render-pipeline-agnostic — Built-in, URP and HDRP all work. PrefabCapsule is an editor tool and does not touch rendering.
  • The core tool has zero package dependencies. Only the optional demo scene requires com.unity.ugui + com.unity.inputsystem.

What gets installed

                  //   Roles, Capsule Health, the UI-Toolkit Inspector, PrefabCapsuleApi,
                  //   the diffable serializer and the CI validator
  Runtime/        // one editor-only marker component (no runtime logic) plus a
                  //   build post-processor that strips it from built scenes
  Demos/          // an interactive demo scene + per-feature sample scenes (open + Play)

ⓘ
Zero runtime footprint. The only thing that ever lives on a GameObject is a marker component with no runtime logic, and a build post-processor removes it from built scenes. Nothing PrefabCapsule does costs you a frame at runtime.

⚡ Quick Start

Seal a prefab, expose one property, guard the asset — in under a minute, no code.

Pick a prefab instance
Select any prefab instance in your scene. Variants, nested prefabs and 2D prefabs all work.
Seal it
GameObject → PrefabCapsule → Seal Selected Prefab (or Add Component → PrefabCapsule). The instance collapses to one node with a lock badge; its children dim in the Hierarchy but stay present at runtime.
Expose what a designer should touch
In the custom Inspector, create a Facet (for example "Designer") and add exposed members to it — a property, a whole component, a method button, a reference, or a child. That curated surface now draws on the collapsed root.
Guard the asset & ship
Toggle Apply Guard so nobody accidentally applies overrides back to the shared prefab (Revert still works). Build normally — the marker component is stripped from the build.
💡
Already have a project full of override chaos? Start with Adopt instead. Point it at an existing prefab instance and it inventories the overrides you already have, then lets you Reveal them as a Facet or Clean them — and can encapsulate the prefab and draft a starter facet for you.
ⓘ
Prefer to see it running? Open the bundled interactive demo scene and the per-feature sample scenes under Assets/PrefabCapsule/Demos/ — open one and press Play to try each pillar hands-on.

⚙ How It Works

The whole tool is one workflow with four moves.

Any prefab instance → Seal → Expose surface → Adopt / Govern → Ship (stripped)
  1. Seal. Add a PrefabCapsule component and the instance collapses to one governed node — a non-destructive dim of the children plus a lock badge on the root. Nothing is deleted; children still exist at runtime.
  2. Expose. Allow-list exactly the members a designer should touch — a property, a whole component, a method button, a UnityEvent, a read-only reference or a child — and group them into named Facets that draw on the collapsed root.
  3. Adopt / Govern. Inventory the overrides an existing project already has and Reveal or Clean them; gate writes with Apply Guard; and filter which Facets each teammate sees with Roles.
  4. Ship. The marker component has no runtime logic, and a build post-processor strips it from built scenes — so the whole workflow costs nothing at runtime.
ⓘ
It is an editor tool, end to end. Every pillar — Seal, Expose, Apply Guard, Adopt, Roles, Health — runs in the Unity Editor against your prefabs and scenes. There is no second component to maintain, no runtime manager, and no per-frame work.

🔒 Seal (Capsule Lock)

Collapse a prefab instance to one governed node so the Hierarchy stops being a wall of children.

Add a PrefabCapsule component to a prefab instance and it becomes a capsule: the root gets a lock badge and its children are dimmed (non-destructively) so the whole thing reads as a single node. The children are still there at runtime — this is an editor-only visualization, not a deletion.

Seal states

StateWhat it does
SealedThe capsule reads as one governed node with a lock badge; children are dimmed in the Hierarchy.
Sealed + HideTransformAs Sealed, and the interior transform hierarchy is hidden for the cleanest possible node.
UnsealedThe capsule is temporarily open — children show normally while you work inside.

Peek

Peek temporarily reveals one capsule’s insides without changing its Seal state, and auto-reverts as soon as your selection moves away. It is the quick "let me look inside for a second" gesture — no toggling, no risk of leaving a capsule open by accident.

Pick Shape — select a sealed capsule in the Scene view

Because a sealed capsule reads as one node, PrefabCapsule lets you click its body in the Scene view to select it. Choose the Pick Shape that best matches the object:

Pick ShapeSelects by
BoundsThe capsule’s bounding box (the default; fast and good for most objects).
MeshThe actual mesh surface — use this for concave geometry where the box is too coarse.
SkinnedA skinned mesh renderer’s surface.
SpriteA sprite’s bounds — for 2D capsules.
RootThe root transform only.
✅
No Gizmos toggle required. Picking a sealed capsule by its body works without the Scene-view Gizmos dependency that older workflows require. And if the prefab is ever unpacked, the capsule self-heals back to a consistent state.

📝 Expose & Facets

The curated surface — allow-list exactly what surfaces on the collapsed root, grouped into persona views.

Once a prefab is sealed, you decide what a teammate is actually allowed to touch. Expose adds individual members to the collapsed root as an allow-list — nothing surfaces unless you put it there.

What you can expose

Exposed memberSurfaces as
A propertyAn editable field for a single serialized property.
A whole componentThe component’s full inspector, inline on the root.
A public methodA clickable button that invokes the method.
A UnityEventThe event, editable inline.
An object referenceA read-only reference field.
A child GameObjectA handle to a specific child.
Header / Comment / SeparatorLayout & documentation items to organize the surface.

Facets — persona views of the same prefab

Group exposed members into named Facets such as "Designer" or "Programmer". Each Facet is a different curated surface of the same prefab, so different team members open the same object and see exactly the controls that make sense for them. Give any exposed member a custom display name — including CJK and other unicode text.

ⓘ
One prefab, many surfaces. A "Designer" facet might expose a handful of tuning properties and a couple of method buttons, while a "Programmer" facet exposes whole components. Pair Facets with Roles to control who sees which.

🛡 Apply Guard

One-way write protection — a strong guardrail against accidentally applying instance overrides back to the shared asset.

Turn on Apply Guard for a prefab and instances of it can no longer Apply their overrides back to the shared source asset. The most expensive prefab accident — one person’s local tweak silently rewriting the prefab everyone depends on — is taken off the table. Crucially, this is one-way: Revert and Revert All always work, so pulling an instance back in line with the asset is never blocked.

Where it holds

  • Apply Guard gates at the instance level, not at the property drawer — so it holds even for custom-drawn and Odin-decorated properties.
  • Revert and Revert All remain available at all times, on guarded and unguarded prefabs alike.
⚠
An honest guardrail, not an absolute lock. No editor guardrail is unbreakable — a determined user with enough Unity knowledge can always find another path. What Apply Guard does is remove the easy footguns: the one-click accidental Apply that quietly corrupts a shared asset. Treat it as strong protection against mistakes, not a security boundary.

🔎 Adopt (Override Scanner)

The standout — the migration path for bringing the workflow to a project that already exists.

Most prefab tools assume a clean start. Adopt assumes the opposite: you already have scenes full of prefab instances with overrides scattered across them. Point Adopt at a prefab instance and it inventories the overrides that already exist across your scenes, grouped by component and by child, so you can finally see the whole picture in one place.

What you do with the inventory

ActionEffect
RevealPromote the overrides you want to keep into a Facet — one click turns "hidden ad-hoc tweaks" into an intentional, curated surface.
CleanRevert the overrides you did not mean to keep — one click to bring instances back in line with the asset.
Encapsulate this prefabAdds a capsule to the prefab and auto-drafts a starter Facet, so you go from "raw prefab" to "governed capsule with a first surface" immediately.
💡
This is how you adopt PrefabCapsule on an existing project. You do not have to rebuild anything. Scan what you already have, keep the good overrides as Facets, clean the accidental ones, and let the encapsulate action seal the prefab and draft its first surface — then govern from there.

👥 Roles

Native team governance — decide which roles may see each Facet.

Roles are built into PrefabCapsule (not a separate add-on). For each Facet you set which roles may see it; the active editor role then filters the visible facets, so each teammate’s Inspector shows only the surfaces meant for them. A designer opening a capsule sees the designer surface; a programmer sees the programmer surface — from the same prefab, with no duplicated assets.

ⓘ
Governance, not access control. Roles shape what the Editor presents to whoever is working, so teams stay focused and out of each other’s controls. Combine Roles with Apply Guard to also protect the shared asset from accidental writes.

🎨 Facet Presets

Reusable Facet definitions you apply to any capsule.

Define a Facet once and reuse it everywhere. A Facet Preset is a ScriptableObject you create with Assets → Create → PrefabCapsule → Facet Preset and apply to any capsule. Standardize the "Designer" surface (or any persona view) across many prefabs instead of rebuilding it by hand each time.

💡
Consistency across a project. Presets make your curated surfaces uniform — every capsule of a given kind exposes the same controls, so teammates always know where to look.

📊 Capsule Health

A project-wide dashboard for the state of every capsule — plus a headless CI validator.

Open Tools → PrefabCapsule → Capsule Health for a project-wide dashboard that flags:

  • Broken exposes — an exposed member whose target child, component or property no longer resolves.
  • Empty sealed capsules — a capsule that seals nothing meaningful.
  • Drift — capsules that have wandered from their intended configuration.

CI validation

The same checks run headlessly. Call the CI validator from your build pipeline and it exits non-zero if any capsule is broken, so a bad capsule fails the build instead of shipping:

// Headless validation entry point — exits non-zero on any broken capsule
PrefabCapsule.Editor.CI.ValidateAllCapsules.Run();C#
ⓘ
Catch problems before they ship. Run Capsule Health interactively while you work, and wire ValidateAllCapsules.Run into CI so broken exposes and drift are caught automatically on every build.

📦 Public API & Diffable Serialization

A scriptable surface for automation, and a version-control-friendly on-disk format.

Scriptable API

Everything the Inspector does is also available through PrefabCapsuleApi — EnsureCapsule, CreateFacet and Expose — so you can script capsule setup, generate facets in bulk, or standardize a whole project from an editor tool of your own. See the Scripting API reference for signatures and snippets.

Deterministic, diffable serialization

Facet configuration is serialized deterministically: regenerating the same configuration produces byte-identical output. That means clean prefab diffs in version control — no noisy churn from re-saving — and it makes the format friendly to code review and CI.

✅
Clean diffs, by construction. Because the serializer is deterministic, two people who build the same facet get the same bytes. Combine that with the CI validator for a workflow that stays honest in a shared repository.

📙 Scripting API

Optional. Everything below is editor-side automation — namespaces PrefabCapsule and PrefabCapsule.Editor.

Create a capsule and expose a property

using PrefabCapsule;
using PrefabCapsule.Editor;

// Ensure the selected GameObject is a capsule
var capsule = PrefabCapsuleApi.EnsureCapsule(go);

// Create a persona view
var facet = PrefabCapsuleApi.CreateFacet(capsule, "Designer");

// Expose the Rigidbody mass of the "Body" child onto the collapsed root
PrefabCapsuleApi.Expose(capsule, facet, new ExposedMember(MemberKind.Property){
    ChildPath     = "Body",
    ComponentType = "UnityEngine.Rigidbody",
    PropertyPath  = "m_Mass"
});C#

Adopt, Health, Guard & serialization

// Adopt: inventory the overrides on an existing instance, then Reveal or Clean
var report = AdoptScanner.ScanInstance(instance);
AdoptActions.RevealOverrides(capsule, report);   // promote into a Facet
AdoptActions.CleanOverrides(instance, report);    // revert the rest

// Capsule Health: scan the whole project
var health = HealthScanner.ScanProject();

// Apply Guard: Revert always works, even on a guarded prefab
ApplyGuardPolicy.RevertAllOverrides(instance);

// Diffable serialization: deterministic, byte-identical for the same config
string text = FacetSerializer.Serialize(capsule);C#

Key types

Type / memberPurpose
PrefabCapsuleApi.EnsureCapsule(go)Return (creating if needed) the capsule on a GameObject.
PrefabCapsuleApi.CreateFacet(capsule, name)Add a named Facet (persona view) to a capsule.
PrefabCapsuleApi.Expose(capsule, facet, ExposedMember)Allow-list a member onto the collapsed root.
ExposedMember / MemberKindDescribes one exposed item (Property, Component, Method, UnityEvent, reference, child, layout items).
AdoptScanner.ScanInstance(instance)Inventory the overrides on an instance, grouped by component + child.
AdoptActions.RevealOverrides / CleanOverridesPromote overrides into a Facet, or revert them.
HealthScanner.ScanProject()Project-wide scan for broken exposes, empty capsules and drift.
ApplyGuardPolicy.RevertAllOverrides(instance)Revert an instance’s overrides — always allowed, guarded or not.
FacetSerializer.Serialize(capsule)Deterministic, diffable serialization of a capsule’s facets.
PrefabCapsule.Editor.CI.ValidateAllCapsules.Run()Headless CI validator; exits non-zero on any broken capsule.
ⓘ
Editor-side by design. The API drives the same editor operations as the Inspector — it is for automation and tooling, not for runtime. There is no runtime API to call because there is no runtime logic.

💡 Troubleshooting

The issues that come up most, and how to fix them.

A sealed prefab isn’t selectable in the Scene view

Set the Pick Shape for the capsule. Bounds is the default and works for most objects; switch to Mesh for concave geometry where the bounding box doesn’t match the visible shape (or Skinned / Sprite / Root as appropriate). No Scene-view Gizmos toggle is needed — picking a capsule by its body works without it.

Capsule Health reports a broken expose

A broken expose means the exposed member’s target — a child, a component, or a property — was renamed or deleted, so the path no longer resolves. Fix the path so it points at the current member, or remove the exposed item if it’s no longer needed. Re-run Capsule Health to confirm it’s clear.

I use Odin Inspector — is it supported?

Yes. Odin support is compiled behind the ODIN_INSPECTOR define, so it activates when Odin is present in your project. Apply Guard also holds for Odin-decorated properties because it gates at the instance level, not at the property drawer.

Will the marker component end up in my build?

No. The marker component is editor-only and carries no runtime logic, and a build post-processor strips it from built scenes. There is zero runtime cost — nothing PrefabCapsule adds survives into the shipped build.

❓ FAQ

Quick answers to the questions that come up most.

Is PrefabCapsule editor-only?

Yes. It is an editor tool with zero runtime cost. The only thing on a GameObject is a marker component with no runtime logic, and a build post-processor strips it from built scenes.

Does it change my prefab data destructively?

No. The Seal is a non-destructive editor visualization — children stay present at runtime and nothing is rewritten on disk. The capsule configuration itself is stored as primitive values and serialized in a deterministic, diffable format.

Can my whole team use it?

Yes — that’s the point. Use Roles so each teammate sees only the Facets meant for them, and Facet Presets to standardize surfaces across many prefabs. Apply Guard protects the shared asset from accidental writes.

Which Unity versions are supported?

Unity 2022.3 LTS or newer. It is compile-verified on 2022.3.56f1 and was developed on Unity 6000.0. It is render-pipeline-agnostic (Built-in / URP / HDRP), since it’s an editor tool that doesn’t touch rendering.

Does it work with Prefab Variants, nested prefabs and 2D?

Yes. Variants, nested prefabs and 2D prefabs all work — and the Sprite Pick Shape is there specifically for selecting 2D capsules in the Scene view.

Is Apply Guard an absolute lock?

No — and we won’t claim otherwise. No editor guardrail is unbreakable. Apply Guard is a strong guardrail against the accidental Apply that quietly corrupts a shared asset; it removes the easy footguns rather than acting as a security boundary. Revert and Revert All always remain available.
