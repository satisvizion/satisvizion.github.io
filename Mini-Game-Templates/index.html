Mini Game Templates

A modular Unity asset for building mini-game collections. The package includes reusable runtime services, category packs, a no-code Studio window, a showcase scene, and the bundled HyperCasual LiveOps Kit backend for ads, IAP, haptics, and mobile game services.

No-code Studio Code-first API Bundled LiveOps backend Separate category assemblies Self-contained HTML docs

Requirements

Unity

Verified in this project with Unity 6000.0.62f1. The package metadata for the bundled LiveOps kit targets 6000.0.

Packages

Core UI uses Unity UI and TextMeshPro. Optional integrations such as Unity IAP, Google Mobile Ads, Firebase, Mobile Notifications, and analytics are installed only when your project needs them.

Platforms

The templates are authored for Unity mobile and desktop editor workflows. Native mobile features remain behind explicit settings and scripting defines.

Installation

Import the asset folder.
The shipped root is Assets/MiniGameTemplates. Do not import ProjectSettings as part of the asset package.
Open the Studio.
Use Tools > Mini Game Templates > Studio. The first import also opens a welcome window once, unless it is dismissed.
Open the showcase scene.
Use the Studio or Welcome button to open Assets/MiniGameTemplates/Demo/MiniGameTemplates_Dashboard.unity.
Press Play.
Select a category and game from the dashboard. The demo wires shared theme, wallet, ads, IAP, and haptics services through the bundled backend.

Quick Start

Buyer click-through path

Open Tools > Mini Game Templates > Studio, edit the Theme or Word List tab, open the showcase scene, press Play, and pick a game. No scripting is required for the demo workflow.

// Optional code-first launch path
using MiniGameTemplates.Core;

MiniGameDescriptor descriptor = MiniGameRegistry.Find("casual_match3");
IMiniGame game = descriptor.Create();
game.Mount(context);

Editor Tools / No-Code

The primary no-code surface is the Studio window. It is additive to the runtime API: code-driven users can still construct games directly, while non-coders can configure common settings through serialized assets and editor buttons.

Studio Window

Menu: Tools > Mini Game Templates > Studio

Tabs include Overview, Theme, Word List, per-category game tabs, Achievements, and About. Category tabs are discovered from installed category providers, so removing a category folder also removes its tab.

Welcome Window

Menu: Tools > Mini Game Templates > Welcome

Shows once on first import, is guarded in batch mode, and provides buttons for Documentation, Showcase Scene, and Studio.

LiveOps Toolset

Menu: Tools > HLK > Open Toolset

Use this for ads, IAP, haptics, notifications, game services, remote config, consent, and other backend setup. The documentation button resolves back to this file.

Saved Config Assets

Common config is stored under Assets/MiniGameTemplates/Resources/Config so runtime demos and builds can load the same assets edited in the Studio.

Demo Showcase

The dashboard scene demonstrates the complete flow: category discovery, game mounting, shared HUD, rewards, wallet updates, ads placements, IAP product requests, and haptic feedback.

Scripting API

The runtime API is centered around descriptors, contexts, and services. The registry discovers games declared with Mini Game Templates metadata and exposes a stable creation path.

public interface IMiniGame
{
    void Mount(IMiniGameContext context);
    void Unmount();
}

public interface IMiniGameContext
{
    RectTransform Host { get; }
    MiniGameTheme Theme { get; }
    IWallet Wallet { get; }
    IAudioBus Audio { get; }
}

Code-first users

Use MiniGameRegistry, IMiniGame, and IMiniGameContext directly when building custom launchers or embedding one template inside another game.

No-code users

Use the Studio to edit theme and level assets, then run the demo dashboard or copy the demo wiring into your own scene.

HyperCasual LiveOps Kit

The backend is bundled at Assets/MiniGameTemplates/HyperCasualLiveOpsKit. It provides in-engine fallbacks by default and enables vendor SDK backends only when their packages and scripting defines are present.

ModuleDefault behaviorNative/vendor path
AdsSafe no-op or simulated flow for editor demos.Google Mobile Ads and mediation backends through explicit defines.
IAPLocal/dummy purchase flow for editor testing.Unity IAP 5 StoreController backend when Unity Purchasing is installed and enabled.
HapticsEditor-safe fallback.Android/iOS native haptics where available.
ServicesLocal settings, local save, simulated remote/live features.Firebase, Unity Gaming Services, platform services, and other SDKs per module.
Product IDs used in the showcase

The demo requests sample products such as mgt.coins.1000, mgt.noads.lifetime, and mgt.starter.bundle. Replace them with your store IDs before shipping a game.

Troubleshooting

The documentation button says the file is missing.

Confirm that Assets/MiniGameTemplates/Documentation/Documentation.html exists. If you moved the asset root, keep the same internal folder structure or update the editor helper paths.

Ads or IAP do not call a native SDK.

Install the required vendor package, then enable the matching HLK scripting define in the LiveOps toolset. Until then, the package intentionally uses editor-safe fallback backends.

The dashboard shows no category tabs.

Check that at least one category provider assembly is present under Runtime/<Category>/Editor and that Unity compiled without errors.

A word game has too few words.

Open the Studio Word List tab, assign a text asset or paste words inline, then click Rebuild Index.

FAQ

Can I remove categories I do not need?

Yes. Category packs live in their own assemblies. The main Studio discovers installed providers and hides missing category tabs.

Does the asset change my ProjectSettings?

The asset should be exported without ProjectSettings. Some runtime settings such as frame rate and sleep timeout can be applied by LiveOps settings in play mode or builds when you configure them.

Does the package send network traffic by default?

No network-capable LiveOps features are configured by default. Vendor SDKs and remote endpoints become active only after you install and configure them.
